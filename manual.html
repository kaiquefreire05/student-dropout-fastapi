Manual da API de previsão de evasão estudantil

Guia de execução manual e integração do front-end com a API FastAPI.

Importante: a API prevê Dropout (evasão) ou não evasão (Graduate/Enrolled). O modelo usa o alvo binário: 1 = Dropout e 0 = Graduate ou Enrolled.

1. Executar manualmente

Pré-requisitos

  • Python 3.10 ou superior;
  • pip instalado;
  • terminal aberto na raiz do projeto, onde está requirements.txt.

Linux/macOS

cd /caminho/para/student_dropout_fastapi
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

Windows PowerShell

cd C:\caminho\para\student_dropout_fastapi
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

Iniciar o servidor

python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

--reload é recomendado durante o desenvolvimento. Para acesso por outros computadores da rede, use --host 0.0.0.0. Endereços: interface, Swagger e ReDoc.

Para verificar a instalação: curl http://127.0.0.1:8000/health. Para executar os testes: python -m pytest tests -v.

2. Endpoints

MétodoCaminhoFinalidade
GET/Interface HTML de teste.
GET/healthVerifica se a API e o modelo estão carregados.
GET/model/infoRetorna features, métricas e informações do modelo.
POST/predictPrevê o risco de um estudante.
POST/predict/batchPrevê o risco de vários estudantes.

As requisições POST devem usar Content-Type: application/json.

3. Inputs do front-end

O formulário deve coletar os 34 campos abaixo. Use campos de seleção para categorias e envie códigos numéricos, não textos. A API aceita nomes originais do dataset, como "Marital status", ou nomes snake_case, como "marital_status". Para um front-end novo, recomenda-se snake_case.

Campos int devem ser inteiros; campos float devem usar ponto decimal; indicadores usam 0 para não e 1 para sim. Recomenda-se enviar todos os campos, mesmo existindo valores padrão no schema.

4. Códigos categóricos

O front-end pode mostrar rótulos traduzidos e manter um dicionário {codigo, label}, mas deve enviar apenas o código original. Exemplos: application_mode: 1 primeira fase/concurso geral, 42 transferência, 43 mudança de curso; course: 9003 agronomia, 9119 engenharia informática, 9500 enfermagem; previous_qualification: 1 ensino secundário, 3 licenciatura, 4 mestrado, 5 doutorado; nationality: 1 portuguesa, 41 brasileira, 22 cabo-verdiana.

Consulte a tabela oficial Variables Table na página da UCI para a lista completa. Os códigos são categorias nominais e não representam uma ordem numérica.

model_accuracyAcurácia de teste, atualmente 0.8667; não é a probabilidade do estudante.
timestampData/hora UTC em ISO 8601.

6. Requisição e retorno de POST /predict/batch

Envie { "students": [ ... ] }, com cada item contendo os mesmos 34 campos de um estudante. A posição é preservada: predictions[i] corresponde a students[i].

{
  "total_students": 2,
  "predictions": [
    {
      "prediction": 1,
      "prediction_label": "Dropout (Evasão Escolar)",
      "risk_level": "Alto Risco de Evasão",
      "dropout_probability": 0.94,
      "retention_probability": 0.06,
      "model_used": "Logistic Regression",
      "model_accuracy": 0.8667,
      "timestamp": "2026-10-16T15:30:00.123456"
    }
  ],
  "summary": {
    "total_students": 2,
    "predicted_dropout_count": 1,
    "predicted_retention_count": 1,
    "dropout_rate_percent": 50.0,
    "average_dropout_probability": 0.48
  },
  "timestamp": "2026-10-16T15:30:00.123456"
}

summary é um agregado da lista inteira, não uma nova predição.

7. Healthcheck e erros

GET /health retorna status, model_loaded, model_name, model_accuracy e timestamp. Considere o serviço pronto quando status for healthy e model_loaded for true.

HTTPSituaçãoFormato típico
400Lote vazio.{"detail":"A lista de estudantes não pode ser vazia."}
422JSON inválido ou tipo incorreto.Objeto detail com localização e mensagem de validação.
500Falha durante a inferência.Objeto detail com a mensagem do erro.
503Modelo não carregado em /model/info.Objeto detail informando indisponibilidade.

A probabilidade é uma estimativa estatística, não uma certeza ou diagnóstico individual. Fonte: Realinho et al. (2021), UCI Machine Learning Repository.
